# 최종 관측·충전 설정 v3

기본 미로와 새 학습의 크기는 **64×64**입니다. 자동으로 작은 미로로 바꾸지 않습니다.
기존 v2의 20만 스텝 모델은 비교 자료로 보존하며 이번 입력 구조에 이어 학습하지 않습니다.

## 실행

최신 작업 브랜치의 파일을 기존 폴더에 덮어쓰고 `train_ppo.bat`에서 1번을 선택합니다.
`.venv`, `runs`, 이전 모델 파일은 지우지 않습니다. 기존 Python 3.12 환경을 사용합니다.

- 1: 최신 v3 이어 학습. 없으면 64×64 새 학습
- 2: 독립적인 64×64 v3 새 모델
- 3: 크기를 명시적으로 선택하는 고급 옵션. 선택하지 않으면 64×64 유지
- `watch_ppo.bat`: 일반 탈출 상황 재생 (항상 시작점에서 출발)
- `watch_return_ppo.bat`: 같은 크기의 미로에서 귀환·충전 연습 상황 재생
- `sync_ppo.bat`: 업로드 대기 백업 재전송

매 실행 추가 10만 스텝, 약 1만 스텝마다 GitHub 저장입니다.
릴리스 이름은 `ppo-v3-...`, 루트 백업은 `ppo_v3_model.zip`과 `ppo_v3_model.json`입니다.
이전 `ppo-run-` 및 `ppo-v2-` 모델은 자동 이어 학습 대상에서 제외합니다.
학습은 PC에서 실행되며 GitHub는 저장소입니다. 기존 CLI 로그인은 재사용합니다.

## 시야 규칙

- 현재 칸과 바로 좌우의 진입 가능 여부를 확인합니다.
- 전방 1~3칸은 해당 칸과 바로 좌우 통로를 확인합니다. 따라서 교차로의 연결을 구분합니다.
- 전방 4칸부터는 직선 축의 통로와 첫 벽까지만 확인합니다. 그 칸의 좌우는 새로 드러나지 않습니다.
- 벽이 있으면 관측을 멈추며 모퉁이 너머로 이어지는 통로 내부는 보이지 않습니다.
- 먼 거리에서는 통로 길이만 제공하고, 처음 보는 출구 같은 표식은 3칸 안에 들어와야 식별합니다.
- 이전에 가까이에서 관측한 지형·교차로·출구 정보는 멀어져도 기억에 남습니다.

정책은 기존 9×9 자기 방향 기준 주변 기억과 위치·배터리 등 상태에 더해
전방 직선 통로 길이를 미로 크기로 정규화한 입력을 받습니다. v3 상태 벡터는 16개입니다.
실제 전체 지도, 숨은 출구 좌표, 정답 경로, 연습 상황 구분은 정책 입력이 아닙니다.
시뮬레이터는 전체 기억을 유지하지만 정책에 들어가는 지도는 주변 9×9라는 기존 한계는 유지됩니다.

## 충전

시작점에서 충전 행동을 선택하면 **2턴 후 완충**합니다. 도착만으로 충전되지는 않습니다.
횟수 제한은 없고 충전 뒤에도 관측·방문 기억이 유지됩니다.
충전이나 귀환 자체에 추가 양의 보상은 주지 않습니다. 반복 충전으로 점수를 얻을 수 없습니다.
이동/회전 에너지 1/0.5, 초기 용량 = 최소 턴 경로 에너지 ×1.25는 기존과 같습니다.
보상은 v2의 실제 첫 방문/시간/충돌/연속 회전/탈출 규칙을 그대로 사용합니다.
시야 변경을 위해 전진 보상을 추가로 올리지 않았습니다.

## 충전 연습 구성 (학습용)

기본적으로 매 판 70%는 일반 출발, 30%는 귀환 연습 생성을 시도합니다. 비율은 임시 학습 설정입니다.
모든 미로는 64×64로 생성됩니다.

일반 출발: 시작점·완충 상태에서 출발합니다. 충전이 필요 없으면 바로 탈출해도 됩니다.

귀환 연습: 초기 관측부터 실제로 2~5칸을 사전 이동한 관측 기억을 제공하고,
잔량을 '올바르게 시작점에 돌아갈 에너지 +1'로 설정합니다. 다음 조건을 모두 만족할 때만 채택합니다.
1. 남은 에너지로 시작점까지 돌아갈 수 있음
2. 남은 에너지만으로 출구에 도달할 수 없음
3. 귀환 후 완충하면 출구까지 갈 수 있음

조건에 맞지 않으면 같은 미로의 일반 출발로 되돌립니다. 그래서 실제 연습 비율은 30%보다 낮을 수 있습니다.
사전 이동은 모델이 선택한 행동이나 학습 보상으로 계산하지 않습니다. 이는 실제 시작점 출발 평가와 구분되는
인위적인 연습 시작 상태입니다. 일반 평가에서는 이 기능을 끕니다.
연습 생성의 도달 가능성 검사는 평가자용 경로 계산을 사용하지만 그 경로나 비용을 정책에 주지 않습니다.
돌아갈 길의 기억은 사전 이동 중 실제로 관측된 것만 남깁니다.

연습 상황이 있다고 AI가 귀환·충전을 배웠다고 보장할 수는 없습니다. 충전 후 탈출까지의 결과를 확인해야 합니다.
기본 최대 턴은 4×크기² (64×64이면 16,384턴), 24행동 연속 제자리 중단 규칙은 유지합니다.

## 기록과 평가

`metrics.json`의 `scenarios` 안에 일반 출발(`navigation`)과 귀환 연습(`return_practice`)을 나누어 기록합니다.
각각 완료 판수, 탈출 수, 귀환 판수, 충전 판수, 귀환 후 충전 판수, 충전 후 탈출 판수, 실제 충전 횟수가 있습니다.
`episodes.csv`에는 위 상황과 충전 후 이동 횟수도 들어갑니다.
`charged_after_return`은 실제로 귀환한 뒤 충전을 완료했을 때만 참입니다.
전체 학습 성공률에는 두 상황이 섞이므로 단독 성능 지표로 사용하지 않습니다.

일반 탈출 평가 (연습 시작 비활성):
```
python -m training.evaluate --run runs/실행폴더 --episodes 100 --seed 20000
```
귀환 연습 평가:
```
python -m training.evaluate --run runs/실행폴더 --episodes 100 --seed 20000 --practice
```
출력의 scenarios로 실제 구성된 상황을 확인합니다. 후보가 성립하지 않으면 일반 시작으로 대체됩니다.
v2 7×7 성능과 v3 64×64 성능은 크기와 관측 규칙이 다르므로 성공률만 직접 비교하지 않습니다.

## 검증 범위

- 자동 검사 39개: 시야의 3/4칸 경계, 벽 차폐, 기억 유지, 2턴 충전, 기본 크기 및 관측 유효성,
  v2와 v3 저장 격리, 연습 상태 재현성과 귀환/충전/탈출 가능성을 포함합니다.
- 연습 가능성 검사는 정답 경로로 수행한 환경 검사이며 AI의 학습 성공을 의미하지 않습니다.
- 실제 64×64 v3 PPO 2,048스텝 및 추가 256스텝 이어 학습, 주기 저장, 로드, 일반/연습 화면 없는 재생 확인.
- 2,048스텝 짧은 실행에서는 탈출 0회였습니다. 이번에는 기능 동작만 검증했고 충전 전략의 습득은 미확인입니다.
- Windows BAT/GUI의 이번 수정본은 이 Linux 환경에서 직접 실행하지 못했습니다.

## 결과 자동 저장 (요약 추가)

학습을 저장할 때마다 다음 파일도 함께 갱신합니다.
- 실행파일 옆 `ppo_v3_model_summary.txt`: 가장 최근 학습 결과 요약, 메모장으로 확인
- `runs/실행폴더/training_summary.txt`: 해당 실행의 결과 요약
- `runs/실행폴더/training_history.csv`: 저장 시점별 성공률 추이 (Excel에서 열 수 있음)
- 기존 `metrics.json`, `episodes.csv`: 기계 판독용 통계와 판별 기록

학습 요약·추이도 GitHub checkpoint ZIP에 함께 저장됩니다.
통계는 이번 실행의 완료된 판 기준이며, 일반 탈출과 귀환 연습을 분리합니다.
평균 턴은 성공과 실패 모두 포함한 값이므로 탈출 경로 효율과 혼동하지 않아야 합니다.

별도 테스트는 `evaluate_ppo.bat`를 더블클릭합니다.
- 1: 일반 시작점 출발 평가
- 2: 귀환·충전 연습 평가

GitHub 최신 v3를 다운로드하고 고정 시드 20000부터 100개 미로를 평가합니다.
최대 확률 행동과 확률적 행동을 각각 같은 시드 100개로 평가하므로 총 200판이 실행됩니다.
학습 가중치는 변경하지 않습니다. 시간은 각 판 길이에 따라 달라집니다.

결과는 다운로드한 실행 폴더의 `evaluations` 아래 UTC 시각별 파일로 저장합니다.
- `.txt`: 성공률, 평균 턴, 배터리 부족, 충전 관련 결과
- `.csv`: 결과 비교용 표
- `.json`: 평가 원본 수치
- `.metadata.json`: 모델 SHA256, 누적 스텝, 환경 설정, 평가 종류 등 식별 정보

평가 결과 묶음(`evaluation-....zip`)도 해당 GitHub Release에 업로드합니다.
업로드가 실패하면 로컬 결과가 남으며 `sync_ppo.bat`로 재시도할 수 있습니다.
평가 ZIP은 모델 체크포인트와 이름이 달라서 자동 이어 학습 대상으로 선택되지 않습니다.
같은 시드 결과를 반복적으로 튜닝에 이용하면 그 결과에 맞출 위험이 있으므로, 최종 평가에는 별도 시드도 사용합니다.

요약 추가 검증: 42개 자동 검사 통과, 실제 짧은 학습 요약/추이/루트 사본 생성,
별도 평가의 TXT·CSV·JSON·메타데이터 자동 생성 확인. 공통 업로드 함수는 모의 CLI로 검사했으며,
새 평가 결과의 실제 GitHub 업로드는 아직 미검증입니다. 모델 구조와 보상 변경이 아니므로 v3 재학습은 필요 없습니다.

## 1. 프로젝트 정체성과 일정

- 과목: 대학 **인공지능응용**.
- 주제: **강화학습 기반 동적 환경 적응형 의사결정 모델 개발**.
- 본질: 제한된 관측과 탐색 기억을 가진 학습된 AI가, **처음 보는 미로**를 추가 학습 없이 탐색하고 출구에 도달하는지 검증한다.
- 사용자는 실제 개발·실험에 시간을 투입하고, ChatGPT는 설계 검토, 코드 작성·수정, 실험 절차 정리, 결과보고서 작성에 협력한다.
- **중요 일정:** 2026-10-19 기준 약 1주 안에 교수에게 **결과보고서 초안**을 제출하여 피드백을 받아야 한다. 프로젝트 구현은 그 뒤에도 계속된다.
- 이 문서는 **기획서 제출**을 뜻하지 않는다. 보고서는 **결과보고서**이며, 실험하지 않은 결과를 만들어내면 안 된다.
- 사용자는 관련 논문/오픈소스의 **방향성과 유용한 구현만 선별적으로 활용**하고자 한다. 기존 프로젝트를 통째로 복제하거나 요구사항을 기존 라이브러리에 맞춰 변경하지 않는다.

## 3. 확정된 환경 요구사항

### 3.1 미로
- **32×32 기본**, **64×64 확장**. 8×8·16×16 등 작은 미로로 디버깅/커리큘럼 가능.
- 다양한 시드 및 생성 방식으로 훈련·평가용 미로를 만든다.
- 시작점/출구 사이의 연결성을 보장하고 BFS로 검증한다.
- 출구는 AI가 직접 탐색해서 발견해야 한다.

### 3.2 AI가 아는 정보와 모르는 정보
- 시작 시 아는 것: **미로의 가로세로 크기, 자신의 현재 좌표, 바라보는 방향, 행동 규칙**.
- 시작 시 모르는 것: **벽·통로의 전체 배치, 출구의 위치**.
- 전체 지도, BFS 경로, 숨겨진 출구 좌표는 **환경·사용자 화면·평가자 전용**이다. 정책 관측값이나 보상 계산 결과를 통해 AI에 부주의하게 유출하지 말 것.
- 부분 관측: 현재 방향으로 보이는 제한된 시야, **벽 뒤는 가려짐**. 구체적인 시야 거리·각도는 아직 확정하지 않았으므로 실험 가능한 파라미터로 설계한다.

### 3.3 행동
- 전진 한 칸, 좌회전 90°, 우회전 90°.
- **각 행동은 1턴**을 소모한다.
- 벽에 전진을 시도하면 이동하지 않지만 턴은 소모하고, 필요시 충돌 페널티를 적용한다.

### 3.4 탐색 기억
- 별도 명시적 탐색 지도: **미관측 / 통로 / 벽 / 발견한 출구**.
- 과거 관측을 유지해 이미 확인한 길을 활용하고, 필요하면 되돌아갈 수 있어야 한다.
- 미로 구조가 바뀌어도 AI는 자동으로 그 사실을 알지 못한다. **재관측한 후에만** 기억을 갱신한다.
- 탐색 지도 같은 **에피소드별 상태**는 테스트 중 갱신 가능하지만, **신경망 가중치**는 테스트 중 갱신 불가.

## 4. 학습 및 평가 원칙

- Python에서 미로를 대량 생성해 **오프라인 강화학습**한다.
- 우선 알고리즘 후보는 **PPO**. 검증된 오픈소스 구현체 활용 가능. PPO 채택 자체는 초기 후보이며 성공 보장은 없다.
- 테스트용 웹은 **고정된 사전 학습 모델의 추론**에만 사용한다. 웹에서 학습하거나 테스트 도중 가중치를 업데이트하지 않는다.
- 훈련 시드와 평가 시드/미로를 분리하여 일반화 성능을 측정한다.
- 초기부터 32×32/64×64에 PPO가 안정적으로 성공할 것이라고 가정하지 않는다. 필요하면 작은 미로부터 커리큘럼 학습을 시도한다.
- **비강화학습 frontier 탐색 기준선**을 구현하면 환경 검증과 비교 실험에 유용하다. 그러나 이것만을 학습된 AI라고 표현하면 안 된다.
- 비교 가능한 실험 지표: **탈출 성공률, 평균/중앙 턴 수, 탐색한 칸의 비율, 중복 방문, BFS 최단 경로 대비 실제 이동 효율**, 실패 원인.
- 실제 학습 결과가 나오기 전에는 수치·그래프를 추정값으로도 '실험 결과'처럼 작성하지 않는다.

### 4.1 보상/종료 설계 — 실험으로 검증할 후보
- 새로 관찰한 칸: 소량의 양의 보상.
- 출구를 처음 발견: 추가 보상.
- 출구 도착: 큰 성공 보상과 에피소드 종료.
- 시간/턴 소모: 소량 페널티.
- 벽 충돌: 페널티.
- 의미 없는 반복, 오랜 탐색 정체: 선택적 페널티나 **조기 에피소드 종료**.
- **정상적인 되돌아가기**는 미로 탐색에 필수일 수 있으므로 무조건 실패로 처리하지 않는다.
- 정체 종료는 **실패한 에피소드를 일찍 종료**한다는 뜻이지 기존 학습 가중치를 삭제하거나 실시간으로 모델을 재훈련한다는 뜻이 아니다.
- 비교 실험 후보: 기본 보상 vs 신규 발견 보상, 정체 종료 유무, 기억 입력 유무.
- 보상 편법(reward hacking)·목표 미발견 상태에서의 장기 탐색을 주의한다.

## 5. 웹 테스트 UI — 후속 개발 요구사항

- **왼쪽 사용자 관점**: 전체 미로, 출구, AI 위치·방향, 전체 이동 궤적, BFS 최단 경로.
- **오른쪽 AI 관점**: 현재 시야, 발견한 통로·벽, 미관측 영역, 기억 지도.
- 기본 속도는 **약 1턴/초**, 속도 조절(예: 0.25~10배/최대), 일시정지, 한 턴 진행, 통계 표시.
- 사용자는 **실행 전** 미로를 편집하거나 직접 제작할 수 있다.
- **실행 중** 벽 추가/제거 가능. 추가 후에도 **현재 에이전트 위치에서 출구까지 BFS 경로가 남아야 함**. 실행 전에는 시작점에서 검사.
- 편집 결과를 AI에 직접 알려주지 않는다. AI가 직접 관찰·기억을 수정한다.
- 실행 중 미로 수정에 대응하는 **실시간 정책 추론**이 필요하다. 사전 녹화된 이동 기록만 재생하는 방식은 요구사항을 충족하지 못한다.
- 웹 UI는 **학습이 아니라 테스트·시각화**에 사용한다.

참고 후보:
1. Parisotto & Salakhutdinov, **Neural Map: Structured Memory for Deep Reinforcement Learning**, ICLR 2018 — https://arxiv.org/abs/1702.08360  
   공간적 기억 아이디어. **논문의 학습형 neural memory와 프로젝트의 명시적 탐색 지도는 동일한 기술이 아님**.
2. Hausknecht & Stone, **Deep Recurrent Q-Learning for Partially Observable MDPs** — https://arxiv.org/abs/1507.06527  
   부분 관측에서 순환형 신경망 활용 참고. 반드시 DQN으로 구현하라는 뜻은 아님.
3. Mirowski et al., **Learning to Navigate in Complex Environments** — https://arxiv.org/abs/1611.03673  
   탐색·보조 학습 과제 참고.
4. Burda et al., **Exploration by Random Network Distillation** — https://arxiv.org/abs/1810.12894  
   내재적 신규성 보상 아이디어. **신규 칸 개수 보상과 RND는 다름**.
5. Farama Foundation, **MiniGrid** — https://github.com/Farama-Foundation/Minigrid  
   격자 이동, 방향, 부분 관측, 시야 구현 참고 또는 라이브러리 활용 후보.
6. MiniGrid 예제 코드 **rl-starter-files** — https://github.com/lcswillems/rl-starter-files

**중요:** MiniGrid 사용은 확정되지 않았다. 우리의 요구사항(방향별 시야, 명시적 기억 지도, 실시간 미로 변경, 테스트 웹)에는 **간단한 자체 Gymnasium 환경**이 더 빠를 수도 있다. 기존 코드와 통합 비용을 비교한 뒤 결정하라. 가져온 코드에는 원저작자·라이선스를 명시하고 호환성을 확인하라.

## 7. 보고서 인계 사항

- 사용자에게 교수의 **HWP 결과보고서 양식**과 **학생 예시 결과보고서 3종**이 이전 대화에서 제공되었다. 새 Work 대화에 첨부되어 있지 않을 수 있으므로 **실제 파일을 확인하지 않고 템플릿의 세부 서식을 재현했다고 주장하지 말 것**. 필요하면 사용자에게 해당 파일 재첨부를 요청한다.
- 보고서는 **결과보고서 초안**, 제안서/기획안이 아니다. 작성 당시 완료된 개발과 아직 진행 중인 실험을 구분한다.
- 알려진 양식의 큰 목차:
  1. 개발과제의 필요성
  2. 개발기술의 독창성 및 차별성
  3. 개발과제의 내용 (최종 목표 / 세부기술개발 내용)
  4. 개발과제에 대한 실험결과
  5. 개발성과의 활용방안 및 기대효과 (기술적 / 경제적 / 사회적)
  6. 참고문헌
  7. 소스코드
- **실험결과를 지어내지 말 것**. 실제 코드, 테스트 로그, 실패 사례, 개선 과정, 향후 실험 계획을 명확히 구분해 작성한다.
- 가능하면 개발 단계마다 **실행 방법, 테스트 로그, 실험 설정/시드, 성공·실패 사례, 스크린샷/그래프**를 저장해 보고서에 활용한다.

## 8. 사용자 개발 환경과 협업 방식

- 사용자 PC: **RTX 4080 SUPER 16GB VRAM, RAM 64GB**, CPU는 i9-13900K로 언급되었으나 세부 확인 필요.
- **실제 GPU 강화학습은 사용자 PC에서 실행**하고, ChatGPT는 실행 명령과 코드, 분석·수정 사항을 제공한다. 외부 작업 환경에서 사용자의 GPU를 직접 사용할 수 있다고 가정하지 말 것.
- GitHub를 작업 기준점(source of truth)으로 사용한다.
- 코드 변경 시 가능한 범위에서 테스트 후 커밋하고, **실행으로 확인한 사항과 코드만 작성한 사항을 구분**한다.
- 설계 미확정 요소는 합리적인 초기값을 정해 테스트 가능하게 만들되, 이를 '사용자 확정 요구사항'이라고 적지 않는다.
- 과도한 기능 추가보다 **작동하는 최소 실험과 제출 기한**을 우선한다.

## 9. Work에 요청하는 다음 작업 (우선순위)

1. 저장소를 읽고 기존 파일의 상태 및 테스트 결과를 확인한다. 필요하면 발견된 버그를 수정한다.
2. **이동·회전·충돌 규칙**과 에이전트 상태(위치·방향)를 구현한다.
3. **방향별 제한된 시야/벽 차폐**와 **명시적 탐색 기억 지도**를 구현한다. 전체 미로·출구 좌표가 정책 관측값에 노출되지 않는지 테스트한다.
4. 위 기능을 **Gymnasium 환경**으로 구성하고, 행동·관측·보상·종료·시드 재현성 테스트를 작성한다.
5. **작은 미로에서 PPO 최소 학습 및 고정 모델 평가**를 구성한다. 실행 결과를 검증하고 학습 로그를 저장한다.
6. 위 과정에서 보고서에 활용할 수 있는 실험 기록을 남긴다.
7. 이후 32×32/64×64 학습 개선과 웹 UI로 확장한다.

## 10. 범위 구분

사용자가 별도로 구상 중인 **개인화된 AI 보스가 등장하는 소울라이크 게임**은 이 대학 과제와 **완전히 별개의 프로젝트**다. 해당 게임의 학습·기억·보스 설계를 이 미로 프로젝트의 요구사항에 섞지 말 것.
